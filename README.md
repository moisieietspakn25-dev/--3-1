# Лабораторна робота 10 — Unity: бюджет текстур

Навчальний проєкт до курсу «Розробка мультимедійних застосунків». Тут лежить: дванадцять текстур без стиснення, які разом займають **156 МБ** відеопам'яті при бюджеті **24 МБ**. Ваше завдання — вкластися в бюджет і пояснити кожне рішення. Повний текст завдання — у методичці (PDF). Цей README доповнює методичку: розділ [«Уточнення до методички»](#уточнення-до-методички) нижче — **прочитайте його до початку роботи**.

Сцена — це ще й невелика гра, у яку можна пограти: зберіть 8 монет і золотий ключ. Дивіться, як змінюється вигляд гри, коли ви стискаєте текстури.

## Що потрібно
- **Unity 6000.3.9f1** (Unity 6.3). Інша версія 6.x теж має відкрити проєкт, але Inspector може трохи відрізнятися.
- URP (вже налаштований).
- Модуль **Android Build Support** (Unity Hub → Installs → ⚙ → Add modules). Він потрібен, щоб формат ASTC працював так, як у методичці (пояснення нижче).
- Python 3 — для калькулятора, який ви пишете самі (завдання 1).

## Як почати
1. Клонуйте репозиторій і відкрийте теку через Unity Hub (**Add → Add project from disk**). Перший імпорт триває кілька хвилин.
2. Відкрийте сцену `Assets/Scenes/TextureBudgetLab.unity`.
3. Перемкніть платформу на Android: **File → Build Profiles → Android → Switch Platform** (перемикання переімпортує текстури, зачекайте). Без цього кроку ваші зміни на вкладці Android не буде видно в Inspector і профайлері — див. нижче.
4. Натисніть **Play** і пограйте — це ваш «стан до». Далі виконуйте завдання 1–4 з методички.

## Гра
Знайдіть **8 монет** і **золотий ключ**. Коли все зібрано — перемога й час проходження.

| Клавіша | Дія |
|---|---|
| `W A S D` | рух (відносно камери) |
| `Shift` | біг |
| `Пробіл` | стрибок |
| `Tab` | перемикач камери: фіксована ↔ слідкуюча (у слідкуючій `ПКМ` + миша повертає камеру) |
| `R` | почати заново |

- **Червоні плями** на землі відбирають здоров'я (25 од./с).
- **Масляна пляма** сповільнює рух.
- **Ящики** можна штовхати, бочки й будівлі — ні.
- **Жовта стрілка** на землі вказує на ключ.
- Одну монету видно на ящиках — залізьте на нижній ящик і стрибніть.

Гра стартує з **фіксованою камерою** (`Main Camera` не рухається) — саме з неї робіть скріншоти «до/після». Не змінюйте її положення в сцені. Персонаж на скріншоті має стояти на стартовій позиції (не рухайте його до скріншота або натисніть `R`).

## Що є в сцені

`Assets/Textures/` містить рівно 12 текстур зі списку методички:

| Текстура | Розмір | Де використана |
|---|---|---|
| `Ground_Albedo` / `Ground_Normal` | 2048² | земля (`M_Ground`) |
| `Building_Albedo` / `Building_Normal` | 2048² | цегляні будівлі (`M_Building`, `M_Building_Tall`) |
| `Props_Albedo` / `Props_Normal` | 1024² | ящики й бочки (`M_Props`) |
| `Skybox` | 2048² | небо (`M_Sky`, шейдер Skybox/Panoramic) |
| `Character_Albedo` / `Character_Normal` | 1024² | персонаж (`M_Character`) |
| `UI_Atlas` | 2048² | весь інтерфейс (смуга HP, кнопки, панель із текстом, іконки) |
| `Decals` | 1024² | наклейки на землі: масло, тріщини, стрілка, червона пляма (`M_Decal_*`) |
| `Noise` | 512² | деталізація землі (Detail Albedo в `M_Ground`) |

Монети й ключ мають однотонний матеріал без текстур, тож бюджет вони не змінюють. На `UI_Atlas` навмисно є шрифти від 22 до 11 px і різкі межі — саме тут видно, що ламає блокове стиснення. Напис «Журнал місії» й кнопки теж взято з атласу; смуга здоров'я — це рамка з атласу плюс червона заливка, яку гра розтягує за поточним HP.

### Початковий стан імпорту
Усі текстури: **RGBA32 без стиснення, з міпмапами, Max Size 2048**, без перекриттів для платформ. Саме так виходить 156,00 МБ. Контрольні значення в Inspector: 2048² → 21,33 МБ, 1024² → 5,33 МБ, 512² → 1,33 МБ.

Початковий стан sRGB: **увімкнений** для всіх кольорових текстур (`*_Albedo`, `Skybox`, `Decals`, `UI_Atlas`), **вимкнений** для нормалей і для `Noise` (це службові дані, не колір).

Щось зламали й не можете повернути? Меню **Lab → Reset Texture Import Settings (156 MB)** повертає всі текстури до початкового стану (ваші налаштування буде втрачено).

## Уточнення до методички

Ці пункти перевірені на цьому проєкті в Unity 6000.3.9f1 і розширюють або уточнюють текст методички.

### 1. Платформа має бути Android, інакше нічого не змінюється
Методичка радить увімкнути вкладку платформи (Android/iOS) й виставити там формат. Але Inspector і профайлер показують розмір для **активної** платформи збірки. Якщо активна Standalone (Windows/Mac/Linux), то після зміни на вкладці Android цифра внизу Inspector **не зміниться** — ви побачите ті самі 21,33 МБ і подумаєте, що налаштування не спрацювало. Тому спершу: **File → Build Profiles → Android → Switch Platform**. Потрібен модуль Android Build Support.

Якщо Android-модуля немає, а ставити його ніколи: на вкладці Standalone формат ASTC приймається, але для ASTC 4×4 Unity на десктопі фактично дає DXT5 (там теж 8 біт, тож розмір збігається); для 6×6 і 8×8 цього не перевірено, і числа плану можуть не підтвердитися. Надійний шлях — Android.

### 2. Unity покаже трохи більше, ніж калькулятор, для ASTC 6×6
Методична формула дає ASTC 6×6 для 2048² з міпмапами **2,37 МБ**, а Unity показує **2,38 МБ**, для 1024² — 0,59 проти 0,60. Причина: сторона 2048 не ділиться на 6, тож останній ряд і стовпець блоків дописуються до повного блоку, і те саме на кожному рівні міпмап. Розбіжність близько 0,5 % — це не помилка в калькуляторі. Для 4×4 і 8×8 (сторони кратні 4 і 8) числа збігаються точно.

Приклад із цього проєкту (Android): план нижче дає за калькулятором **15,80 МБ**, у Unity — **15,84 МБ**.

На захисті цю різницю треба вміти пояснити; саме порівняння «порахував / побачив у Unity» і є суттю завдання 4.

### 3. Прапорець sRGB: що перевірено
Усі зміни я перевірив у Linear-просторі (Edit → Project Settings → Player → Color Space = Linear — так налаштований проєкт).

- **`Noise`** використаний як Detail Albedo землі й множить колір на 2 (мультиплікатор «середнього сірого»). Якщо sRGB увімкнено, середній сірий (0,5) перетворюється в лінійних 0,21, і земля **темніє приблизно вдвічі**. Саме це описує методичка: «потемніли поверхні». Тому для `Noise` sRGB має бути **вимкнено** (так і є спочатку); спробуйте ввімкнути й подивіться.
- **Нормалі** (`Texture Type: Normal map`) — sRGB вимкнено автоматично, чіпати не треба.
- **`UI_Atlas`**: методичка (завдання 3, п. 5) просить зняти sRGB «для інтерфейсу». Але атлас містить **колір** (зелена, синя, червона кнопки, іконки), і в Linear-просторі вимкнений sRGB робить інтерфейс **блідим і вицвілим** — спробуйте й порівняйте скріншоти. Пам'ять від прапорця не залежить. Тож рішення за вами: спробуйте обидва варіанти, зробіть скріншот і обґрунтуйте вибір (це добра відповідь на питання 6 з розділу «Запитання на здачі»). Орієнтир: sRGB вимикають для даних (нормалі, маски, шум), а не для кольорових зображень.

### 4. Цифри профайлера в Editor
- У режимі Editor профайлер (і `Profiler.GetRuntimeMemorySize`) може показувати **вдвічі більше** за Inspector: Editor тримає ще й копію текстури в CPU-пам'яті. Для порівняння «до/після» беріть **однакові умови** і записуйте, що саме міряли (Inspector, Profiler у Editor, Profiler у збірці).
- Профайлер у «Memory» враховує й ресурси, яких немає у вашому списку (методичка вже згадує lightmap, шрифти). У цій сцені це, зокрема, **шрифт інтерфейсу** (динамічний атлас шрифту) і текстури за замовчуванням. Тому загальна цифра буде більшою за суму 12 текстур — і це нормально.
- Найточніша цифра для кожної текстури — рядок унизу Inspector (за умови активної платформи Android).

### 5. Платформа без ASTC (завдання «якщо залишився час»)
ETC2 в Unity на вкладці Android — це «RGB Compressed ETC2 4 bits» і «RGBA Compressed ETC2 8 bits». Для нормалей беріть RGB (4 біти), для `Decals` і `UI_Atlas` з прозорістю — RGBA (8 біт). Перевірено: для 1024² з міпмапами Unity показує 0,67 МБ (RGB, 4 біти) і 1,33 МБ (RGBA, 8 біт) — як у таблиці методички.
